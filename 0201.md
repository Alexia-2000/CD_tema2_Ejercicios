## Tarjeta CRC: 'Socio'

| Clase: Socio | |

| Solicitar el préstamo de un libro  | `Préstamo` `Libro`|

## Tarjeta CRC: 'Préstamo'

| Clase: Préstamo | |
|---|---|
|**Responsabilidades** | **Colaboradores** |
| Conocer que libro y que socio están implicados | `Libro` `Socio` |
| Conocer la fecha de inicio del préstamo | - |
| Registrar la devoluciuón del préstamo | `Libro` |

### 2. Relación entre las clases 
 Comprobaciones previas: 
   El objeto `Libro` verifica el "número de ejemplares disponibles".
   Condición de éxito: El número de ejemplares disponibles debe ser mayor que 0.
   Condición de fallo: Si el número de ejemplares disponibles es igual a 0, el préstamo se rechaza.

 Si el préstamo TIENE ÉXITO (Ejemplares > 0):
  El objeto disminuye en 1 su contador de "ejemplares disponibles".
  Colabora con la clase 'Préstamo' para permitir que se registre la nueva transacción.
  Devuelve una confirmación positiva para indicar que el proceso fue exitoso.

 Si el préstamo NO TIENE ÉXITO (Ejemplares = 0):
  El objeto no realiza ningún cambio en sus atributos (el número de ejemplares disponibles se mantiene en 0).
  No se genera ninguna colaboración con 'Préstamo'.
  Devuelve un indicador de fallo indicando que no hay stock disponible.

#### 3. Describe el flujo
Paso 1: Se da de alta 3 ejemplares.
Descripción:
Se instancia un nuevo objeto de la clase 'Libro' asignándole su título, autor, ISBN y fijando el atributo de "ejemplares disponibles" en 3 libros.

Paso 2: se dan de alta 2 socios.
Descripción:
Se instancian dos objetos independientes de la clase 'Socio', registrando para cada uno su nombre, número de socio y fecha de alta.

Paso 3: El primer socio roma prestado un libro.
Descripción:
  - El primer 'Socio' solicita el préstamo.
  - Se invoca a la clase 'Libro' para verificar disponibilidad. Como tiene 3 ejemplares (mayor que 0), el préstamo ¡SÍ TIENE ÉXITO!.
  - El 'Libro' reduce sus ejemplares disponibles a 2.
  - Se crea una instancia de 'Préstamo' que se conecta con este 'Socio' y este 'Libro', guardando la fecha de inicio.

Paso 4: El segundo socio intenta tomar el mismo.

Clase que actúa: 'Socio' (inicia la acción).
Colaboradores: 'Préstamo' y 'Libro'.
Descripción:
  - El segundo 'Socio' solicita el préstamo.
  - Se consulta al 'Libro', el cual tiene 2 ejemplares disponibles (mayor que 0), por lo que el préstamo ¡SÍ TIENE ÉXITO!.
  - El 'Libro' decrementa sus ejemplares disponibles a 1.
  - Se crea otra instancia de 'Préstamo' que vincula al segundo 'Socio' con el 'Libro'.


Paso 5: El primer socio devuelve el libro.

Clase que actúa: 'Socio' (inicia la acción).
Colaboradores: 'Préstamo' y 'Libro'.
Descripción:
  - El primer 'Socio' solicita la devolución.
  - La clase 'Préstamo' actúa para registrar la devolución y notifica al 'Libro'.
  - El 'Libro' recibe la devolución y aumenta sus ejemplares disponibles de 1 a 2.


Paso 6: El segundo socio vuelve a intentar tomar el libro.

Clase que actúa: 'Socio' (inicia la acción).
Colaboradores: 'Préstamo' y 'Libro'.
Descripción:
  - El segundo 'Socio' solicita un nuevo préstamo del mismo libro.
  - Se consulta al 'Libro', que actualmente cuenta con 2 ejemplares disponibles (gracias a la devolución del Paso 5).
  - Como el valor es mayor que 0, el préstamo ¡SÍ TIENE ÉXITO!.
  - El 'Libro' vuelve a disminuir sus ejemplares disponibles a 1 y se genera un nuevo objeto 'Préstamo' para este registro.
